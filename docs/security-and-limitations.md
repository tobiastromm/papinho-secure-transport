# Trust, security, readiness, and limitations

PST requires TLS 1.2 or newer and fails closed. It does not silently downgrade, bypass hostname validation, union CUSTOM_TRUST with SYSTEM_TRUST, or fall back to plaintext. mTLS client identity is explicit certificate DER plus unencrypted PKCS#8 DER; server authentication and client authentication are distinct. Required ALPN mismatch fails.

CUSTOM_TRUST is an application-supplied CA set for private, corporate, laboratory, or pinned deployment PKI. SYSTEM_TRUST delegates to a capable provider. OpenSSL's Windows adapter performs per-connection Windows chain evaluation without PST online revocation, AIA fetching, or root auto-update during evaluation. Enterprise/Group Policy stores are structurally inherited but are not domain-runtime certified here. A future PapinhoTrustStore could be a portable, versioned, authenticated CUSTOM_TRUST source; it is not implemented and PST is not a public root program.

Operations are incremental and bounded. READ/WRITE/READ_WRITE readiness means retry may be useful, not that TLS progressed. A received TLS `close_notify` is CLEAN; unexpected EOF/reset is TRUNCATED. Graceful shutdown completes after reciprocal `close_notify`; if PST sends `close_notify` and the peer then closes TCP without replying with its own alert, the provider may report unexpected EOF and PST preserves it as `PST_RESULT_TRUNCATED`. Plaintext received before close remains deliverable. Shutdown is incremental.

Diagnostics are copied normalized result/operation/backend-ID snapshots, not a global last-error and not native error disclosure. Logging is a temporal stream of structured events; diagnostic snapshots are copied normalized state. Logging levels OFF=0 through TRACE=5 are cumulative. Callbacks are synchronous; events are ephemeral and context is caller-owned. PST provides no worker or file logger. The public event and diagnostic records have no fields for hostnames, application payload, certificate DER, keys, trust material, paths, native handles/pointers, or arbitrary native provider error codes. Applications remain responsible for sanitizing any data they add to their own logs.

Built-in providers have different advertised capabilities. Selection is constrained by the requested policy and selection mode; PST does not imply that providers are interchangeable or that every provider supports every TLS version or trust model. PST handles secure transport within its documented contract. The application remains responsible for its protocol semantics, authorization decisions, credential handling outside PST, and application-level data behavior.

## Tested and not claimed

Real evidence covers Windows NT 4.0 SP6 for the preserved NSS package and Windows 10 build 19045 for Schannel, plus modern-host OpenSSL tests. It does not imply Windows 2000, XP, 95, 98, Win32s, every Windows build, or every enterprise domain configuration. Current public support does not claim POSIX adapters, dynamic plugins, session resumption, 0-RTT, a public full-chain API, DTLS, QUIC, Noise, FIPS certification, formal verification, or universal revocation behavior.

In the 0.6.5 release candidate, OpenSSL, Schannel and RetroZilla NSS implement the SERVER role. OpenSSL supports TLS 1.2/1.3, CUSTOM/SYSTEM trust and complete SERVER ALPN semantics. Schannel SERVER supports validated TLS 1.2 and CUSTOM/SYSTEM trust, but does not advertise TLS 1.3 on the validated environment or complete PST SERVER ALPN semantics. RetroZilla NSS SERVER supports TLS 1.2/1.3 and CUSTOM trust, but does not advertise SYSTEM trust or complete PST SERVER ALPN semantics. The Windows trust adapters apply server-auth plus hostname verification for CLIENT peers and client-auth without hostname semantics for SERVER peers. Successful certificate authentication does not authorize an application identity; authorization remains the consumer's responsibility. Raw EOF/reset before reciprocal `close_notify` remains `PST_RESULT_TRUNCATED` for SERVER as well as CLIENT.

The canonical API 2.0/SPI 3.0 negative and lifecycle closure evidence is in [security-lifecycle-negative-matrix.md](security-lifecycle-negative-matrix.md). It covers transactional configuration, ownership acceptance, terminal-state invariants, trust/auth/policy failure, provider pinning, external-state cleanup and bounded malformed input. It is deterministic negative testing, not a comprehensive fuzzing, formal-verification or general thread-safety claim.

## Current API 3.0 / SPI 4.0 Model E contract

The current candidate is library 0.6.5 (0x00000605UL), public API 3.0.0 and provider SPI 4.0. API 3 removes the legacy void connection release and requires `pst_connection_try_release` with the 28-byte `PST_RELEASE_INFO` Model E disposition contract. SPI 4 requires failure-aware `connection_try_close` before infallible final destruction.

The preceding API 2.2 candidate added `pst_transport_termination_info_init(PST_TRANSPORT_TERMINATION_INFO *)` and `pst_connection_copy_transport_termination(const pst_connection *, PST_TRANSPORT_TERMINATION_INFO *)`; those immutable transport-termination facts remain available in API 3. `PST_TRANSPORT_TERMINATION_INFO` remains 32 bytes, while the independent Model E `PST_RELEASE_INFO` V1 contract is exactly 28 bytes.

valid=0 means no event was observed. valid=1 with UNKNOWN means an event was observed but not classified portably. native_code_valid=0 means unavailable; otherwise native_domain names the provider namespace and native_code is an opaque 32-bit pattern. TLS result, portable FIN/RST/SOCKET_ERROR/UNKNOWN, and optional native evidence are independent. Native evidence is diagnostic, not causal proof or authority for trust, PST_RESULT_TRUNCATED, retry, fallback, framing, shutdown, ownership or selection.

The first event is immutable while the connection exists. close_notify alone does not establish FIN; timeout, wake, local cancel and release fabricate no event. After peer close_notify, read may report CLOSED/CLEAN; later application read/write are invalid while get_interest and reciprocal shutdown remain available until shutdown_step reaches final CLOSED. That intermediate bookkeeping state is private. Fatal/truncated states remain terminal, with exactly-once release and no resurrection.

NSS maps factual NSPR EOF/reset/socket errors, Schannel maps recv zero/WSAECONNRESET/socket errors, and OpenSSL maps unexpected EOF or reliable SSL_ERROR_SYSCALL socket evidence; ambiguity remains UNKNOWN. No provider switches after binding. VC6/NSS /ML and /MD remain distinct; Browser uses /MD and Accelerator the governed x64 OpenSSL target.
